ESCRO P2p
Escro is a non-custodial peer-to-peer (P2P) crypto escrow software platform built on the BNB Smart Chain (BSC).

## Security Architecture
- **Non-Custodial:** User funds are held by self-executing smart contracts, not corporate servers.
- **Access Control:** System administration and dispute arbitration are protected by Safe 2-of-3 and 3-of-4 multisig accounts.
- **ERC-4337 Support:** Compatible with Account Abstraction paymasters for gasless user execution.

Know the trade steps before you commit crypto
You can discuss and agree the terms with the merchant in the trade chat while the trade is still CREATED. Do not authorize the crypto lock until you understand and accept the offer. Creating a trade does not itself lock your assets.

Look for Escro’s verified status when choosing a merchant. Verified merchants are subject to platform rules and review and may be held accountable for violations, but verification does not guarantee a successful trade or recovery. Escro’s plan is to build a network of up to 50 verified merchants; this is a growth target, not a claim that all 50 are currently available.

1. CREATED

Review and discuss
Use the trade chat to clarify the terms with the merchant before you lock any crypto. Check the asset, network, amount, payment method and instructions.

2. CRYPTO_LOCKED

Lock only when ready
After the crypto seller authorizes the lock and the network confirms it, the trade moves to escrow. Verify the status in Escro before the buyer sends fiat.

3. FIAT_SENT

Verify the payment
The buyer marks fiat as sent. The seller must independently check their bank or payment account before releasing crypto; never trust screenshots or alerts alone.

4. COMPLETED

Confirm completion
The seller authorizes release and the on-chain transaction completes. A completed release is generally irreversible. If there is a problem, keep communication and relevant evidence in the trade chat and use the dispute flow.

If a buyer cancels before marking payment sent while the trade is still LOCKED, a successful on-chain cancellation returns the crypto to the seller. If an unpaid trade remains LOCKED past its deadline, the seller may claim a timeout refund. Disputes and refunds depend on the contract state and successful on-chain action; support cannot reverse crypto already released to the buyer.

Network Requirement (BSC / BEP-20 Only)
Escro is a non-custodial Web3 platform. The smart contracts used for Escro trades operate on the BNB Smart Chain (BSC).

Use the BSC network (BEP-20) for connected wallets and transactions. Check the selected network before sending assets. Sending assets on an unsupported network can result in permanent loss.

Bringing Native Bitcoin to BSC (BTCB)
Escro operates on BNB Smart Chain, so native Bitcoin (Bitcoin Layer 1) cannot be sent directly to its smart contracts. BTCB is a wrapped version of Bitcoin on BSC.

If you hold native BTC, use a reputable exchange or cross-chain bridge to move it. When withdrawing to your wallet, select BSC (BEP-20) so it arrives as BTCB. Always verify the asset and network before confirming a transfer.

Choose a wallet that works for you
Escro offers an optional embedded wallet and supports external wallets. The embedded wallet can be convenient in the app, but it does not guarantee faster transactions; wallet approval and blockchain conditions affect timing. Review wallet recovery and security options before choosing.

Keep secrets private
Never share your seed phrase, private key, password, recovery code or one-time code with a merchant, another trader or support. Avoid posting unnecessary personal or bank details in chat or evidence. Keep trade discussion in Escro and verify payments in your own payment app.
